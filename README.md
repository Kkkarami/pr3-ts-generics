## 3. Реалізація завдання

### 3.1. Базові типи та інтерфейси (Рівень 1)

Створено інтерфейс `BaseEntity`, який визначає спільні поля сутностей:

- `id` — унікальний ідентифікатор;
- `createdAt` — дата створення;
- `updatedAt` — дата останнього оновлення.

Реалізовано універсальний інтерфейс `ApiResponse<TData>` для стандартизації відповідей із підтримкою різних типів даних.

Також створено `IRepository<T>`, який визначає основні операції роботи із сутностями:

- `create()` — додавання сутності;
- `findById()` — пошук за ідентифікатором;
- `findAll()` — отримання всіх записів;
- `deleteById()` — видалення за ідентифікатором.

### 3.2. Реалізація In-Memory Repository

Створено клас `InMemoryRepository<T extends BaseEntity>`, який реалізує роботу з даними в оперативній пам'яті за допомогою масиву.

Клас підтримує додавання, пошук, отримання всіх записів, видалення та оновлення сутностей.

Для пошуку неіснуючого запису повертається `null`, а для невдалого видалення — `false`.

### 3.3. Статуси сутностей та Utility Types (Рівень 2)

Створено перелік `EntityStatus` із трьома можливими станами:

- `ACTIVE`;
- `ARCHIVED`;
- `DRAFT`.

Для моделювання товару створено інтерфейс `Product`, який успадковує `BaseEntity` та містить поля `title`, `price` і `status`.

Реалізовано утилітарні типи:

| Тип | Призначення |
|---|---|
| `Omit<T, K>` | Виключення системних полів при створенні сутності |
| `Partial<T>` | Дозволяє часткове оновлення |
| `Pick<T, K>` | Формує скорочене представлення сутності |
| `Record<K, V>` | Створює типізований словник даних |

На їх основі створено:

- `CreateDto<T>` — тип для створення сутностей;
- `UpdateDto<T>` — тип для часткового оновлення;
- `EntitySummary<T>` — скорочене представлення товару;
- `EntityAnalytics<T>` — типізована структура статистики за статусами.

### 3.4. Оновлення сутностей

До класу `InMemoryRepository` додано метод `update()`.

Він знаходить сутність за ідентифікатором, застосовує передані зміни та автоматично оновлює поле `updatedAt`.

Системні поля виключені з DTO оновлення, тому через нього не можна змінити первинний ключ `id`.

## 4. Встановлення та запуск

Клонування репозиторію:

```bash
git clone https://github.com/Kkkarami/pr3-ts-generics.git
```

Перехід до каталогу:

```bash
cd pr3-ts-generics
```

Встановлення залежностей:

```bash
npm install
```

Запуск програми:

```bash
npx tsx src/index.ts
```

Перевірка TypeScript:

```bash
npx tsc --noEmit
```

## 5. Демонстрація роботи програми

У файлі `src/index.ts` створюється екземпляр універсального репозиторію для сутності `Product`.

Під час виконання програми:

1. Створюється товар із назвою `Carrot`, ціною `20` та статусом `ACTIVE`.
2. Товар додається до репозиторію.
3. Виконується пошук товару за ID `prod-001`.
4. Здійснюється часткове оновлення назви на `CarrotUpd` та ціни на `30`.
5. Отримується список усіх товарів.
6. Виконується видалення товару за його ідентифікатором.
